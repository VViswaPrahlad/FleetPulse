# Automotive telemetry dataset comparison

**Verification date: 2026-10-08.** This comparison uses dataset-owner/agency pages, repository metadata, current download endpoint headers, and the cited dataset papers. No dataset archive larger than 20 MB was downloaded; in fact, no dataset files were downloaded or sampled. A `HEAD` request checks a resource response and byte length, not its contents.

## Summary

**VED (Vehicle Energy Dataset) is the strongest verified fit** for FleetPulse: its author-maintained repository documents OBD-II time series, timestamps, vehicle/trip keys, speed, latitude/longitude, and fuel rate, and states an Apache-2.0 license. Two directly downloadable archive parts returned HTTP 200 to header-only checks on the verification date. Together they are 176,386,679 bytes (about 176.4 MB decimal / 168.2 MiB), before extraction.

NGSIM is an accessible, larger trajectory table with useful road-relative movement data, but has no fuel target or GPS and the legacy full-export endpoint currently returns HTTP 410. highD and UAH-DriveSet are not recommended for this portfolio at present because current direct access and dataset-specific reuse terms could not be verified.

## Candidate suitability details

### VED for PySpark and local storage

The week-organized CSV input is well suited to schema normalization, timestamp validation, per-vehicle/trip quality checks, sensor null coverage, coordinate validation, speed-derived features, and partitioned Parquet. The source is not so large that distributed infrastructure is justified. PySpark local mode can demonstrate reproducible ETL, but should be configured conservatively and should not be used to imply production scale.

The known compressed input is about 176.4 MB. Uncompressed source size, Bronze/Silver/Gold output sizes, temporary extraction size and exact row count are **unknown until files are inspected**. Set a hard 5 GB working budget and measure each layer. If necessary, process selected weeks or a documented complete subset while retaining provenance. Do not commit downloaded datasets to GitHub.

### What the coordinate fields mean

- VED README lists `Latitude[deg]` and `Longitude[deg]`: geographic coordinate fields, subject to privacy-aware map handling.
- NGSIM records video-derived road-relative coordinates (`local_x`, `local_y`) and global/projected coordinates. These are not GPS.
- highD positions come from drone video and are road/trajectory coordinates, not GPS.

For road-relative-only data, build a Plotly XY/lane trajectory view in native coordinate units with site metadata and a roadway schematic. Label axes as road-relative coordinates/feet or the source's verified units; never label these plots latitude/longitude or GPS maps.

## Remaining checks before full ingestion

The VED recommendation is a source-level selection, not a claim that the data have been quality-audited. After approval, inspect a small, permitted sample and verify actual CSV schemas, timestamp cadence, `VehId`/`Trip` consistency, sensor missingness and fuel-rate support by powertrain, duplicate rows, GPS privacy implications, compressed archive integrity, extracted byte count and projected Parquet footprint before processing the full source.
